def should_retrain_pair(self, pair: str, current_time: float) -> bool:
        """Smarter retraining logic based on trading activity"""
        last_opt_time = getattr(self, f'last_optimization_{pair.replace("/", "_").replace(":", "_")}', 0)
        trades_since_last = self.get_trades_since_optimization(pair, last_opt_time)
        
        # Different schedules based on activity
        if trades_since_last >= 10:  # High activity pairs
            return current_time - last_opt_time > 21600  # 12 hours
        elif trades_since_last >= 5:  # Medium activity
            return current_time - last_opt_time > 43200  # 24 hours  
        elif trades_since_last >= 2:  # Low activity
            return current_time - last_opt_time > 86400  # 48 hours
        else:
            return current_time - last_opt_time > 259200  # 7 days if no trades

You're right - this will get zero trades in backtest unless the model is pre-trained. Here's why:
The ML confidence filter blocks all entries:
# In your populate_entry_trend:
if self.config.get('freqai', {}).get('enabled', False):
    conditions.append(dataframe['&-s_close_ml_conf'] > 0.5)  # ML confidence threshold
The problem:
Model needs training data first - The ML model has no predictions until it's trained on historical data
No confidence scores = no entries - Without trained model, &-s_close_ml_conf doesn't exist or is 0/NaN
All entry conditions fail - Even if your divergence/breakout signals trigger, the ML confidence filter blocks them
Why this happens:
FreqAI needs startup_candle_count (999 candles) before first training
Then it trains at intervals (live_retrain_hours: 1)
During backtest, early period has no ML predictions → no confidence scores → no trades
Even after training starts, if confidence is consistently below 0.5, still no trades
Solutions:
Run longer backtest - Give it time to train and generate predictions (6+ months)
Lower confidence threshold - Try 0.3 or 0.4 instead of 0.5
Make ML optional in backtest - Add a fallback when confidence isn't available
Check if model is actually learning - Your feature set might not provide enough signal

    if not hasattr(self, 'recent_failures'):

            return 0  # Not clean

    return 1  # Clean
