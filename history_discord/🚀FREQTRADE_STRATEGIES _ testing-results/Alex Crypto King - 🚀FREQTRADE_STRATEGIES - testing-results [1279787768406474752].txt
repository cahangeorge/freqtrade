u can add the following in the main class and play around using "protection" in hyperopt, one is enabled one is disabled in below snippet:
`
    enable_cooldown_protection = True
    optimize_cooldown_protection = True
    use_cooldown_period = BooleanParameter(default=enable_cooldown_protection, space="protection", optimize=optimize_cooldown_protection)
    cooldown_lookback = IntParameter(2, 48, default=24, space="protection", optimize=optimize_cooldown_protection)

    enable_stop_protection = True
    optimize_stop_protection = True
    use_stop_protection = BooleanParameter(default=enable_stop_protection, space="protection", optimize=optimize_stop_protection)
    trade_limit = IntParameter(2, 4, default=4, space="protection", optimize=optimize_stop_protection)
    stop_duration = IntParameter(12, 200, default=5, space="protection", optimize=optimize_stop_protection)
    only_per_pair = BooleanParameter(default=False, space="protection", optimize=optimize_stop_protection)

    @property
    def protections(self):
        prot = []
        if self.use_cooldown_period.value:
            prot.append({
                "method": "CooldownPeriod",
                "stop_duration_candles": self.cooldown_lookback.value
            })
        if self.use_stop_protection.value:
            prot.append({
                "method": "StoplossGuard",
                "lookback_period_candles": 24 * 3,
                "trade_limit": self.trade_limit.value,
                "stop_duration_candles": self.stop_duration.value,
                "only_per_pair": self.only_per_pair.value
            })

        return prot
`

from freqtrade.strategy import IStrategy, RealParameter, DecimalParameter, IntParameter, BooleanParameter

get_date_range() {
    local start_days_ago=$1
    local end_days_ago=$2
    local start_date=$(date -v-${start_days_ago}d +%Y%m%d)
    local end_date=$(date -v-${end_days_ago}d +%Y%m%d)
    echo "${start_date}-${end_date}"
}

# Set date ranges
HYPEROPT_RANGE=$(get_date_range 40 10)
BACKTEST_RANGE=$(get_date_range 10 0)

# Download data
docker run --rm -v ./user_data:/freqtrade/user_data \
    freqtrade_image download-data \
    --days 180 \
    -c $CONFIG_FILE \
    -c $CONFIG_FILE_LOCAL \
    --timeframe 1h 2h 4h

# Run hyperopt
docker run --rm -v ./user_data:/freqtrade/user_data \
      -it freqtrade_image hyperopt \
      --timerange=$HYPEROPT_RANGE \
      --spaces buy sell roi stoploss trailing \
      -e 1000 \
      --strategy $STRATEGY \
      --hyperopt-loss SharpeHyperOptLossDaily \
      --config $CONFIG_FILE \
      --config $CONFIG_FILE_LOCAL

# Run backtesting
docker run --rm -v ./user_data:/freqtrade/user_data \
      -it freqtrade_image backtesting \
      --timerange=$BACKTEST_RANGE \
      --strategy $STRATEGY \
      --cache=none \
      --config $CONFIG_FILE \
      --config $CONFIG_FILE_LOCAL

        target_horizon = 1  # Define your prediction horizon here
        shifted_T = dataframe["T"].shift(-target_horizon)
        shifted_T_sell = dataframe["T_sell"].shift(-target_horizon)

        # Initialize &-target to 0 (hold signal by default)
        dataframe["&-target"] = 0

        dataframe.loc[shifted_T > self.threshold_buy.value, "&-target"] = 1
        dataframe.loc[shifted_T_sell < self.threshold_sell.value, "&-target"] = -1

        dataframe["&-target"] = dataframe["&-target"].fillna(0)

        logger.info(f'Targets: {dataframe["&-target"].value_counts()}')

```def populate_entry_trend(self, df: DataFrame, metadata: dict) -> DataFrame:
        enter_long_conditions = [
            df["do_predict"] == 1,  # Only enter if prediction is allowed
            df["&-target"] == 1,  # Buy signal from combined logic
            df["volume"] > 0,  # Ensure there is volume
        ]

        enter_short_conditions = [
            df["do_predict"] == 1,  # Only enter if prediction is allowed
            df["&-target"] == -1,  # Sell signal from combined logic
            df["volume"] > 0,  # Ensure there is volume
        ]

        # Populate long entries
        df.loc[reduce(lambda x, y: x & y, enter_long_conditions), ["enter_long", "enter_tag"]] = (
            1,
            "long",
        )

        # Populate short entries
        df.loc[reduce(lambda x, y: x & y, enter_short_conditions), ["enter_short", "enter_tag"]] = (
            1,
            "short",
        )

        logger.info(f"entry:\n {df.tail()}")
        return df```

Backtesting Traps
Backtesting is important to understand the performance and behaviour of your strategy, but there are a number of issues which can result in a backtest producing much better results than are likely once the strategy is run live (or dry-run).


[09/07/2024 11:09] maxgorbachevskiy
> When backtesting at any timeframe, Freqtrade has only candle data to work with. It doesn’t know how the price moved during the candle. With 1m or 5m candles, it’s less of a problem (although it still exists), but with longer timeframes, like 1h, 4h, etc… Freqtrade needs to make some major assumptions about the order of events.
> 
> As mentioned in the official documentation on Backtesting, when Freqtrade calculates trailing stoploss, it first moves the price to the high, moves the trailing stop up to match accordingly, and then moves the price down, possibly triggering the new trailing stop price.
> 
> Backtesting with extremely tight trailing stops essentially gives you a perfect candle trade, selling just below the high of the candle, almost every time.
> 
> The longer the timeframe you use, the less realistic this is. With a small trailing stoploss, it’s exceptionally unlikely that the price would move directly from open to high without decreasing enough to trigger the stoploss. If your stoploss is smaller than the spread on the pair you’re trading, the stoploss will likely be hit on the next sell trade. The longer the timeframe, the more likely your trailing stop, or even your default stoploss, will be triggered before reaching the high and then falling

Personally, my approach depends on the type of strategy being tested:

Standard Strategies: I usually conduct a dry-run for 3 months. During this period, I review performance and fine-tune parameters bi-weekly to ensure the strategy is optimized.

Machine Learning (ML) Strategies: For some of the more recent strategies from Alex that utilize ML, the timeframe is much shorter. Because the models adapt more efficiently, I’ve found that a 2-3 week dry-run is often sufficient before moving to live trading.

The decision to go live ultimately depends on whether the dry-run results (profitability and drawdown) align with the backtesting expectations across those specific periods.
