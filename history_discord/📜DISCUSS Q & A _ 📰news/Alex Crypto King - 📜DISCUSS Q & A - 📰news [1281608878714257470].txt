What Does the Switch from Scikit-Optimize to Optuna Mean?

Hyperparameter optimization in Freqtrade involves tuning parameters (e.g., buy/sell thresholds, stop-loss, ROI) to maximize a trading strategy's performance, typically by minimizing a loss function (e.g., profit, Sharpe ratio). Previously, Freqtrade relied on scikit-optimize, a library that uses Bayesian optimization with algorithms like ExtraTreesRegressor to search for optimal parameters. The switch to Optuna, another hyperparameter optimization framework, means Freqtrade now uses Optuna’s algorithms and infrastructure for this task.

The transition, as noted in a Freqtrade GitHub pull request, involves replacing scikit-optimize’s optimization logic with Optuna’s, including its samplers (e.g., NSGAIISampler, TPESampler) and study-based approach. This change affects how users configure and run hyperopt, as well as the performance and features available during optimization. Since Freqtrade’s 2021.4 release, users can define hyperopt parameters directly in the strategy, and this switch builds on that by leveraging Optuna’s more modern and flexible framework.

Switching from scikit-optimize to Optuna in Freqtrade introduces a more modern, flexible, and feature-rich hyperparameter optimization framework. Benefits include better visualizations, pruning for faster runs, dynamic search spaces, and active development. However, it comes with a learning curve, potential dependency bloat, and the need to experiment with samplers for optimal results. Practically, users should leverage Optuna’s NSGAIISampler, pruning, and visualization tools while ensuring sufficient hardware and historical data. For further details, check Freqtrade’s documentation or Optuna’s official site.

@everyone as we where playing with simpleoptuna, here some short review about the posibilities with OPTUNA!

I allready integrated it in AlexBandSniper needs to test, but looks even better


Here's the key difference between your previous SimpleOptuna and the full Optuna integration:
SimpleOptuna (Before)

Fake optimization: Just returned random values without actually running Optuna
No real learning: Parameters didn't improve based on trade results
Static parameters: Same settings for all pairs
No persistence: Lost all "optimization" on restart
Limited scope: Only optimized a few basic entry parameters

Full Optuna Integration (Now)

Real optimization: Actually runs Optuna trials and finds better parameters
Performance-based learning: Uses actual trade profit/loss to optimize
Per-pair optimization: Each trading pair gets its own optimized parameters
Persistent storage: Saves optimization results to SQLite database
Comprehensive scope: Optimizes both entry AND exit parameters
Adaptive: Re-optimizes when performance declines
Scheduled optimization: Runs daily optimization checks

Practical Impact
Before: Your strategy used the same hardcoded parameters for all pairs, with no real optimization happening.
Now: Each pair (BTC/USDT, ETH/USDT, etc.) gets its own optimized parameters based on how that specific pair trades. For example:

BTC might get optimized for longer holds with higher profit targets
ETH might get optimized for quick scalps with tighter stops
Each pair's exit strategy is tailored to its volatility and trading patterns

Bottom Line
You went from fake optimization to real machine learning that adapts your strategy to each pair's unique characteristics and improves over time based on actual trading performance.
