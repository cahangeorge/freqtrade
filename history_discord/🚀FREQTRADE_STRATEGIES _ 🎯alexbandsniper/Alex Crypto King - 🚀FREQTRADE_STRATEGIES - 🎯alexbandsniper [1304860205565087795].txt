[04/02/2026 14:05] miluu5979
gemini says: 
I've checked the AlexBandSniperV6 code and found a massive lookahead bias in the backtests due to how pivot points and divergences are calculated.

In the `pivot_points` function, the code confirms a pivot by looking `window` (7) candles ahead, but then retroactively assigns the pivot to the past candle (`pivot_points_highs[index - window] = current_high`). Because of this, the divergence logic triggers the entry signal immediately after the pivot happens, 7 candles before it would actually be confirmed in live trading.

Additionally, using `.bfill()` on multiple indicators in `populate_indicators` introduces a minor lookahead bias by filling empty rows with future data.

This causes the strategy to have artificially perfect entries in backtests that will not replicate in live trading. You need to shift the divergence signals forward by the `window` length so they trigger only when the pivot is actually confirmed.

the choppiness filter in the current code is basically:

1. calculate natr over a rolling window
2. calculate the highest high and lowest low over the same window
3. calculate the price span as:
span = high_max - low_min
4. then compute choppiness as:
choppiness = 100 * log10(sum(natr over window) / span) / log10(window)
in code style, it is this pattern:
def choppiness_index(high, low, close, window=14):
natr = pd.Series(ta.NATR(DataFrame({'high': high, 'low': low, 'close': close}), timeperiod=window))
high_max = high.rolling(window=window).max()
low_min = low.rolling(window=window).min()
span = (high_max - low_min).replace(0, np.nan)
return 100 * np.log10((natr.rolling(window=window).sum()) / span) / np.log10(window)
the problem with this version is that it uses natr, which is already normalized, and then divides again by the raw price span. that mixes incompatible units and can produce unrealistic values, including negative ones.

a more standard choppiness formula is closer to:
choppiness = 100 * log10(sum(true_range over window) / (highest_high - lowest_low)) / log10(window)
so in simple words:

• sum the true range over the last window candles
• divide it by the total high-low range over the same window
• take log10 of that ratio
• normalize by log10(window)
• multiply by 100
